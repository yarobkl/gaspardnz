# frontend-design

> Local Codex-compatible adaptation, **not** the complete upstream installation. Source: https://github.com/anthropics/skills/tree/main/skills/frontend-design

## Use it for
New interfaces, UX improvements, responsive layout, visual hierarchy, accessibility and component consistency.

## Method
1. Inspect the existing typography, palette, spacing, motion, target users and the page's primary job.
2. Prefer reusing real components and design tokens over adding a second design system.
3. Draft clear states for loading, empty, success, errors, long text, keyboard use and small screens.
4. Keep contrast, focus indicators, semantic markup, touch targets and reduced-motion preferences usable.
5. Compare before/after screenshots and verify on desktop and mobile.

## Guardrails
Avoid generic redesigns. Existing visual identity wins unless the user requests a redesign. Do not invent logos, screenshots or user research.

## Completion contract
Summarize the concrete change or assessment, evidence and commands run, tests passed/failed/not run, risks and next step. Never state that third-party tools or browser automation ran unless they actually ran.
